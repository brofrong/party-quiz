# «Что ответит Аня?» — дизайн

Дата: 2026-10-11

## Цель

Вторая викторина для дня рождения. Именинница сидит за консолью ведущего и вписывает
свой ответ на простой вопрос о себе («Любимое блюдо?»). Затем гости видят вопрос и
4 варианта (её ответ + 3 ложных) и голосуют с телефонов. После открытия ответа
угадавшие получают по очку; ведётся таблица лидеров, в конце — пьедестал.

## Критерии успеха

- В админке есть викторина «Что ответит Аня?» с 15 заранее заполненными вопросами,
  у каждого — 4 ложных варианта. Вопросы можно править, добавлять, удалять, выключать
  и перетаскивать.
- Пока Аня отвечает, ни гости, ни сама Аня не видят ложных вариантов; гости не видят
  даже текста вопроса.
- Если ответ Ани совпал с ложным вариантом, этот вариант не попадает в игру — вместо
  него используется запасной (4-й).
- Гость один раз вводит имя и голосует тапом; до открытия может передумать.
- До открытия гостям не уходят ни правильный ответ, ни чужие голоса, ни распределение.
- После открытия все видят правильный вариант, число голосов и имена; гость видит
  «Угадал! +1» / «Мимо».
- Голоса, очки и имена переживают перезагрузку телефона и рестарт сервера.
- «Угадай кадр» работает как раньше.

## Не входит (YAGNI)

- Таймер, очки за скорость.
- Генерация ложных вариантов ИИ из редактора (варианты заполняются в сиде, дальше
  правятся руками).
- Отдельный «режим ТВ»: ТВ — обычный гость, который просто не голосует.

## Изменения в общем механизме

Сейчас ведущий шлёт действия, а все гости получают один и тот же `publicView`.
Добавляем две необязательные возможности модуля:

```ts
interface QuizModule<C, S, A, PV, HV, PA = never> {
  // ...как было
  /** viewer — кто смотрит (null для неизвестного); модуль может персонализировать вид. */
  publicView(content: C, state: S, viewer: Viewer | null): PV;
  /** Действия гостей. Нет — гостевые действия отклоняются. */
  playerActionSchema?: z.ZodType<PA>;
  reducePlayer?(content: C, state: S, player: Viewer, action: PA): S;
}
type Viewer = { id: string; name: string };
```

- `GameEngine.playerSnapshot(viewer)` — снимок для конкретного гостя; подписка
  `game.onState` передаёт `ctx.user`.
- `GameEngine.playerDispatch(viewer, action)` — проверка схемой, `reducePlayer`,
  `commit()` (сохранение + рассылка). Ошибка модуля → `EngineError` → `BAD_REQUEST`.
- tRPC: `game.act` (guestProcedure) → `playerDispatch`; `profile.setName`
  (guestProcedure, 1–24 символа после trim) — меняет `user.name` через Better Auth,
  чтобы имя жило в сессии гостя и подхватывалось в следующих играх. `me` уже отдаёт
  `user.name`. Анонимное имя по умолчанию (`Anonymous`) считается «не представился».
- Клиент: `Player` получает `{ view, act }`, где `act(action)` вызывает `game.act` и
  показывает toast при ошибке. Общий компонент `NamePrompt` (диалог «Как тебя
  зовут?») и `useMyName()` — для любой интерактивной викторины.
- `frame-reveal` не меняется по смыслу: игнорирует `viewer`, гостевых действий нет.

## Модуль `birthday-guess`

Викторина в сиде: id `birthday`, тип `birthday-guess`, название «Что ответит Аня?».

### Содержимое

```ts
question = { id: string; text: string (непустой); decoys: string[] (ровно 4, непустые); enabled: boolean }
content  = { questions: question[] }  // id уникальны
```

`itemCount` — число включённых вопросов.

### Состояние

```ts
state = {
  index: number,               // позиция среди включённых вопросов; == total → финал
  questionId: string | null,   // чтобы правки контента «следовали» за вопросом
  showScores: boolean,         // таблица очков поверх экрана у всех
  players: Record<userId, name>,
  rounds: Record<questionId, Round>,
}
Round = {
  phase: "answering" | "checking" | "voting" | "revealed",
  answer: string | null,       // ответ Ани
  excluded: number[],          // индексы ложных вариантов, совпавших с ответом
  options: string[] | null,    // 4 варианта в порядке показа, фиксируются при старте голосования
  correct: number | null,      // индекс ответа Ани в options
  votes: Record<userId, number>,
}
```

Раунд без записи в `rounds` считается `answering`. Варианты фиксируются текстом при
старте голосования, поэтому правка вопроса во время голосования не меняет уже
показанное. Отслеживание вопроса по id после правок — как в `frame-reveal`
(`locate/at`): удалённый/выключенный вопрос → показывается тот, что встал на его место.

### Действия ведущего

| Действие | Когда | Эффект |
|---|---|---|
| `next` / `prev` / `goto(index)` | всегда | переход; `index == total` — финальный экран |
| `submitAnswer(text)` | answering, checking | `answer = trim(text)` (непустой), `phase = checking`, `excluded` = ложные варианты, совпадающие после нормализации (регистр, `ё→е`, пробелы и пунктуация по краям) |
| `toggleDecoy(i)` | checking | добавить/убрать `i` из `excluded` |
| `editAnswer` | checking | назад в `answering` (ответ сохраняется в поле) |
| `startVoting` | checking | нужно ≥ 3 неисключённых; `options` = ответ + первые 3 неисключённых, перемешаны `rng`; `phase = voting` |
| `reveal` | voting | `phase = revealed` |
| `reopen` | revealed | назад в `voting` (голоса сохраняются) |
| `toggleScores` | всегда | `showScores = !showScores` |

Недопустимое в текущей фазе действие — no-op (как `reveal` в `frame-reveal`), чтобы
двойной клик не ломал игру. `reset` (общая кнопка «Начать заново») — `initialState`:
очки, голоса и раунды обнуляются, имена тоже (их заново подтянет первый голос).

### Действие гостя

`vote(option: 0..3)` — только в фазе `voting` текущего вопроса и только если у гостя
есть имя (иначе `BAD_REQUEST` «Сначала представься»). Записывает голос (повторный
голос заменяет прежний) и `players[id] = name`.

### Очки

Очко за каждый `revealed`-раунд, где голос гостя совпал с `correct`. Таблица —
по убыванию очков, затем по имени; учитываются гости, голосовавшие хотя бы раз.

### Виды

Публичный (персональный) вид:
- всегда: `index`, `total`, `phase` текущего вопроса (или `final`), `votedCount`,
  `showScores`, `me: { name, score } | null`;
- `answering`/`checking`: только номер вопроса — гости видят «Аня отвечает…»;
- `voting`: `question`, `options`, `myVote`;
- `revealed`: плюс `correct`, по каждому варианту `count` и `names`, `myResult`
  (`correct` / `wrong` / `none`);
- `showScores` или финал: `leaderboard: [{ name, score, place }]`.

Вид ведущего: всё содержимое текущего вопроса (текст, 4 ложных варианта), раунд целиком
(включая живые голоса с именами), список вопросов с фазами для навигации, таблица.

## Клиент

### Гость (`Player`)

Адаптивная вёрстка, один компонент для телефона и ТВ:
- `answering`/`checking`: крупно «Вопрос 3 из 15», «Аня отвечает…» с анимацией.
- `voting`: вопрос + 4 большие кнопки (2×2 на широких экранах, столбик на телефоне),
  выбранная подсвечена; «Проголосовали: 9». Первый тап без имени открывает
  `NamePrompt`, после сохранения имени голос отправляется.
- `revealed`: правильный вариант зелёный, у вариантов полоски с числом голосов и
  именами; на телефоне баннер «Угадал! +1» / «Мимо» / «Ты не голосовал».
- `showScores`: таблица поверх экрана; финал: пьедестал топ-3 + список.
- Маленькая плашка «Ты: Петя ✎» — смена имени.

### Консоль ведущего (`HostConsole`)

- `answering`: «режим Ани» — крупно вопрос, поле ответа, кнопка «Готово» (Enter).
  Ложные варианты не показываются.
- `checking`: ответ Ани (кнопка «Исправить»), 4 ложных варианта с отметкой
  «совпадает» (автоматические уже отмечены, можно переключить), подсказка, какие 3
  пойдут в игру; «Показать гостям» (неактивна, если неисключённых < 3).
- `voting`: варианты с живыми голосами и именами, «Открыть ответ».
- `revealed`: итог, «Скрыть ответ», «Дальше».
- Всегда: навигация по вопросам (как список кадров), «Таблица» вкл/выкл, предпросмотр
  того, что видят гости (`Player` с текущим видом). Горячие клавиши: ←/→ навигация,
  пробел — следующий шаг фазы (кроме ввода текста и открытых диалогов).

### Редактор (`Editor`)

Список вопросов с перетаскиванием (`@dnd-kit`, как в `frame-reveal`), «Добавить
вопрос», удаление, переключатель «включён», поле текста и 4 поля ложных вариантов.
Сохранение тем же `quiz.update`; экспорт/импорт работают без изменений.

## Сид

`content/quizzes/birthday.json` — 15 вопросов о вкусах и привычках именинницы
(еда, напитки, фильмы, путешествия, суперспособность и т. п.) с 4 правдоподобными
ложными вариантами каждый. На проде сид добавится автоматически при старте, так как
викторины `birthday` там ещё нет.

## Ошибки и граничные случаи

- Голос не в фазе `voting` или за несуществующий вариант → `BAD_REQUEST`, клиент
  показывает toast; состояние не меняется.
- Гость отключился до открытия — голос остаётся и считается.
- Правка/удаление текущего вопроса во время голосования: показанные варианты не
  меняются; если вопрос удалён — переход на вставший на его место.
- В викторине нет включённых вопросов → экран «Вопросов нет», действия — no-op.

## Тестирование

- Юнит (логика): переходы фаз и no-op для недопустимых действий; автопометка
  совпадений и нормализация; `startVoting` берёт запасной вариант; смена голоса;
  очки и порядок таблицы; публичный вид не содержит `answer`/`correct`/ложных
  вариантов/чужих голосов до открытия; правки контента во время раунда.
- Юнит (движок/роутер): `game.act` → `reducePlayer`; модуль без гостевых действий
  отклоняет `act`; `profile.setName`; персональный снимок.
- e2e: ведущий, ТВ и два телефона — Аня вводит ответ, гости представляются и
  голосуют, после открытия у угадавшего 1 очко, у второго 0; рестарт сервера
  сохраняет очки.
